# lapis CLI

터미널에서 Lapis vault를 다루는 명령줄 도구. **앱이 떠 있지 않아도 동작한다.**

> **이 문서가 명세다.** `docs/`는 외부 지식 저장소로의 심링크라(`.gitignore` 참조) **저장소를
> 클론한 곳에는 없다.** 설계 결정을 거기에만 두면 다른 머신에서 이 저장소를 열었을 때 읽을
> 수 없고, 근거를 모르는 채로 같은 결정을 다시 내리게 된다.
>
> 그래서 CLI에 관한 것은 저장소 안, 이 파일에 남긴다 — `mcp/README.md`와 같은 방식이다.
> **무엇을 만들었는지보다 왜 그렇게 했는지**를 적는다. 전자는 코드를 읽으면 되지만 후자는
> 적어두지 않으면 사라진다.

---

## 무엇인가

`lapis-mcp`가 **AI에게** 인덱스를 열어주는 창구라면, 이쪽은 **사람과 스크립트에게** 여는
창구다. 같은 캐시를 읽고 같은 랭킹을 쓴다 — `mcp/query.ts`의 `lapisQuery()`가 두 소비자의
공용 핵이다.

```
                 ┌─ mcp/server.ts   (MCP stdio · AI)
lapisQuery() ────┤
                 └─ cli/main.ts     (argv · 사람 · 스크립트)
```

⚠️ **핵을 복제하지 않는다.** 랭킹이 두 벌이 되는 순간 한쪽만 바뀌어도 아무도 모른다 —
`fullTextOptions.ts` 헤더가 경고하는 바로 그 고장이다. CLI는 `mcp/`에서 가져다 쓰고,
`mcp/`는 CLI를 모른다(의존 방향은 한쪽뿐).

## 실행

```bash
cli/lapis search "멀티 윈도우"
```

호출 시점에 esbuild로 번들한다(약 30 ms). 커밋된 산출물이나 사전 빌드 단계를 두면
소스와 어긋나도 아무 신호가 없다 — `mcp/lapis-mcp`가 같은 이유로 같은 방식을 쓴다.

PATH에 두려면 심볼릭 링크를 건다:

```bash
ln -s "$PWD/cli/lapis" /usr/local/bin/lapis
```

> ⚠️ **Windows에서는 Git Bash가 필요하다.** 래퍼가 `#!/bin/sh` 스크립트다. `cmd.exe`·
> PowerShell용 shim은 두지 않았다 — 유지할 진실이 하나 더 늘고, 이 저장소의 주 개발
> 환경은 macOS다. Git Bash에서 `cli/lapis`를 그대로 부르면 된다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `search <질의>` | 풀텍스트(BM25) + 구조 필터. `lapis_query`와 같은 랭킹 |
| `backlinks <노트>` | 이 문서를 참조하는 문서들. 본문 링크 ∪ frontmatter cross-ref |
| `list <facet>` | `tags` · `topics` · `doc-kinds` 값을 빈도순 열거 |
| `links --broken` | 어느 노트로도 해소되지 않는 본문 링크. 대상별로 묶어 참조 수 순 |
| `status` | 어느 vault를 어느 캐시로 읽고 있는지, 낡았는지 |
| `tag rename <이전> <새이름>` | 태그 이름 바꾸기·병합. **기본은 dry-run**, `--apply`가 있어야 쓴다 |
| `index` | 앱 없이 인덱스를 다시 만든다. `--dry-run`이면 만들어만 보고 쓰지 않는다 |
| `open <노트>` | 실행 중인 앱에서 그 노트를 연다. 앱이 꺼져 있으면 켠다 |

### 공통 옵션

| 옵션 | 뜻 |
|---|---|
| `--vault <경로>` | vault 루트. 캐시에 여러 vault가 있을 때 지정 |
| `--json` | 기계가 읽을 형태로. **AI·스크립트는 이걸 쓴다** |
| `--limit <n>` | 기본 10, 상한 50 |
| `--help` | 그 명령의 사용법 |

### `tag rename` 전용

| 옵션 | 뜻 |
|---|---|
| `--apply` | 실제로 쓴다. 없으면 미리보기만 |

**하위 태그가 부모를 따라간다** — `tech`를 `stack`으로 바꾸면 `tech/svelte5`는 `stack/svelte5`가
된다. 경계는 `/`에서만 인정하므로 `technical`은 건드리지 않는다.

이미 있는 태그로 바꾸면 **병합**이고, 미리보기가 그 사실을 경고한다.

⚠️ 쓰기는 앱과 **같은 트랜잭션**(`$lib/safeWrite`)을 탄다 — 백업 → 순차 쓰기 → 실패 시 롤백.
원자적 쓰기·vault 이탈 차단·확장자 화이트리스트도 앱과 같게 다시 보장한다(`cli/io.ts`).
CLI가 더 느슨하면 같은 트랜잭션을 쓰면서 안전성만 갈린다.

⚠️ **앱이 인덱스 생산자다.** CLI가 쓴 것은 앱이 다시 읽어야 검색에 반영된다. 앱이 떠 있으면
watcher가 잡고, 아니면 다음에 vault를 열 때 재색인된다.

### `search` 전용

| 옵션 | 뜻 |
|---|---|
| `--tag <t>` | nested prefix — `tech`를 주면 `tech/*` 전부 |
| `--doc-kind <k>` · `--topic <t>` | 정확 일치. ⚠️ frontmatter 선언 기준이라 폴더와 다를 수 있다 |
| `--min-rel <0~1>` | 상대 점수 하한. 결과가 넓을 때 꼬리를 자른다 |
| `--exclude <prefix>` | vault 상대 **문자열 prefix**. 여러 번 줄 수 있다 |
| `--include-archive` | `_memories` 기본 제외를 해제 |

`--min-rel`이 왜 필요한지는 `mcp/README.md`의 **동작 6번**을 보라 — raw 점수는 질의 간
비교가 안 되고, `rel`은 그 질의 안에서 top-1을 1.0으로 둔 값이다.

## 출력 계약

**기본은 사람용**이다. 정렬된 표, 색 없음, 잘린 건 잘렸다고 표시.

**`--json`은 기계용**이고 `lapisQuery()`의 응답을 **그대로** 낸다. MCP 도구가 돌려주는 것과
같은 모양이라, AI가 MCP로 배운 형태를 CLI에서 다시 배우지 않아도 된다.

⚠️ 사람용 출력의 형태는 **계약이 아니다.** 읽기 좋게 바뀔 수 있다. 파싱해야 하면 `--json`을
쓴다. 이걸 명시해 두는 이유는, 안 적어두면 누군가 `awk`로 사람용 출력을 파싱하고 그게 곧
바꾸지 못하는 계약이 되기 때문이다.

## 실패는 소리내어

`mcp/README.md`와 **같은 오류 종류**를 쓴다: `cache_absent` · `version_skew` · `corrupt` ·
`vault_ambiguous` · `vault_not_found` · `path_not_indexed` · `shard_incomplete` · `no_criteria`.

오류는 stderr로 나가고, `--json`이면 stderr에도 JSON으로 나간다 — 기계가 실패 이유를
파싱할 수 있어야 한다.

### 종료 코드

| 코드 | 뜻 |
|---|---|
| `0` | 성공. **결과 0건도 성공이다** |
| `1` | 질의·캐시 오류(위 `kind`들) |
| `2` | 사용법 오류 — 모르는 옵션, 빠진 인자 |

⚠️ **결과 0건을 실패로 두지 않는다.** 스크립트가 "없음"과 "고장"을 구분할 수 있어야 한다.
`grep`이 0건에 1을 내는 관례를 따르지 않는 건 의도적이다 — 이쪽은 검색이 아니라 질의고,
호출부가 `|| true`를 습관적으로 붙이기 시작하면 진짜 실패도 함께 삼켜진다.

### 모르는 옵션은 조용히 무시하지 않는다

오타난 옵션(`--limt 5`)을 무시하면 **기본값으로 돈 결과를 요청한 결과로 오인**한다.
`2`로 죽고 무엇이 잘못됐는지 말한다.

## 설계 판단

### 왜 앱을 거치지 않나

캐시를 직접 읽는다. 앱이 떠 있을 필요가 없고, 떠 있어도 간섭하지 않는다(읽기만 한다).

vault가 캐시보다 새로우면 `status`가 알려주지만 **막지는 않는다** — `mcp/README.md`의
"staleness는 막지 않고 보고한다"와 같은 태도다. 하드 실패 자체가 판단이고, 이 도구는
판단하지 않는다.

### 헤드리스 인덱싱은 어떻게 도나

**인덱스 생산자는 Rust 하나뿐**이라는 원칙 때문이다(README 설계 원칙). 위키링크·마크다운
링크·프론트매터 추출은 `src-tauri/src/vault.rs`에만 있고, Node에서 다시 짜면 **두 스캐너가
반드시 어긋난다.**

그런데 풀텍스트 shard는 JS MiniSearch로 만든다(`fullTextOptions.ts`). 그래서 앱이 IPC 경계를
두고 하는 분업을 CLI는 **프로세스 경계**로 한다:

```
① lapis.exe --headless export-index  →  Rust가 vault를 훑어 원자료 JSON
② Node가 fullTextOptions.ts로 shard 빌드              (cli/indexBuild.ts)
③ lapis.exe --headless import-index  →  Rust가 순서를 지켜 캐시에 커밋
```

원칙 두 개(생산자 하나 · 옵션 단일 출처)를 다 지킨다.

#### 왜 별도 바이너리가 아닌가

후보는 `[[bin]] lapis-index`였다. Tauri 전체를 다시 링크한 **두 번째 큰 실행파일**을 설치본에
얹게 되고, 사이드카 번들 설정이 늘고, 무엇보다 CLI가 찾아야 할 실행파일이 둘이 된다.
이미 설치돼 있는 앱에 플래그 하나를 더하는 쪽이 배포·발견 양쪽에서 싸다.

#### 왜 `AppHandle`이 꼭 필요한가

캐시 **위치**를 아는 것이 그것뿐이다. `paths::app_data_root(app)`가 플랫폼별 디렉터리 +
identifier + dev 접미사를 정하는데, Node가 그 규칙을 흉내내면 **앱이 읽지 않는 곳에** 인덱스를
쓰게 된다. 그래서 헤드리스도 Tauri 앱을 짓기는 한다 — 다만 설정에서 창 목록을 비우고
이벤트 루프를 돌리지 않는다.

#### ③을 Node가 직접 쓰지 않는 이유

쓰는 **순서가 계약**이기 때문이다: shard → stats → **meta 맨 마지막**. meta가 커밋 지점이라
순서를 뒤집으면 fingerprint는 맞아떨어지는데 내용만 낡은 캐시가 생기고, 그건 오류 없이
**조용히 틀린 검색 결과**가 된다. 규칙을 두 벌로 만들지 않는다.

#### 구버전 앱을 만나면

옛 빌드는 모르는 인자를 **무시하고 평범하게 창을 띄운다.** 그러면 CLI는 사용자가 창을 닫을
때까지 돌아오지 않는다 — 실제로 겪었다. 그래서 vault를 훑지 않는 `cache-info`를 짧은 제한으로
**먼저** 불러 능력을 확인하고, 안 끝나면 "앱을 업데이트하라"고 말한다.

### 앱 조작은 왜 서버가 아니라 argv인가

실행 중인 앱을 조작하려면 IPC가 필요한데, **localhost 서버는 쓰지 않는다.**

- README 설계 원칙이 "네트워킹 코드는 없다"이다.
- 로컬의 **아무 프로세스나** vault를 조작할 수 있는 표면이 생긴다. MCP를 기본 OFF로 두고
  "앱이 정할 수 있는 건 질의를 받아줄지뿐"이라고 못박은 태도와 정면으로 어긋난다.

`tauri-plugin-single-instance`가 리스닝 포트 없이 그걸 한다 — 앱을 다시 실행하면 **argv가
실행 중인 인스턴스로 전달되고** 두 번째 프로세스는 그대로 죽는다.

#### ⚠️ 그 플러그인을 아무 데나 켜면 안 되는 이유 둘

**① 헤드리스를 통째로 삼킨다.** 두 번째 인스턴스는 argv를 넘긴 뒤 `std::process::exit(0)`
한다. 앱이 떠 있는 동안 `--headless`를 부르면 **결과 파일을 쓰지도 않고 성공(0)으로 끝난다.**
→ 헤드리스가 아닐 때만 등록한다.

**② dev와 릴리즈가 서로를 죽인다.** 잠금 키가 `identifier` 하나에서 나오는데 커스터마이즈
지점이 없고, Lapis는 dev와 릴리즈가 그걸 공유한다(`paths.rs` — 릴리즈 경로를 못 바꾸니
dev만 접미사를 붙였다). 양쪽에 켜면 **릴리즈가 떠 있을 때 dev 앱이 안 뜬다.**
→ 릴리즈 빌드에서만 등록한다. dev 앱에 `lapis open`을 쏘면 창이 하나 더 뜬다.

#### 창이 여럿일 때 누가 여나

Rust는 **어느 창이 어느 vault를 열었는지 모른다**(창별 localStorage다). 그래서 묻지 않고
꺼내가게 한다:

1. Rust가 열 것을 담아두고 모든 창에 알린다.
2. 각 창이 **자기 vault를 인자로** 꺼내기를 시도한다. 맞는 창만 받는다(꺼내기는 원자적).
3. 아무도 안 가져갔으면 그 vault를 연 창이 없다는 뜻 → 새 창을 띄우고, **그 창만**
   `vault: null`로 물어 무엇이든 받는다.

**차가운 기동도 같은 경로다.** 앱이 꺼져 있었으면 1번의 알림이 아무에게도 안 닿고, 첫 창이
뜨면서 스스로 물어 받아간다 — 창이 준비됐을 때 묻기 때문에 타이밍 경합이 없다.

3번의 창을 가르는 것은 **창 라벨**이다 — 그 창을 만든 게 Rust이므로 라벨을 이미 안다.
프론트는 자기 vault를 말할 뿐 판정하지 않고, `null`을 넘기는 것도 "무엇이든 달라"가
**아니다**(그렇게 두면 기동 직후 vault가 아직 없는 창이 남의 노트를 가로챈다).

⚠️ 처음엔 새 창을 `index.html?cli-open=1`로 열고 프론트가 `location.search`를 보게 했다.
**동작하지 않는다** — `WebviewUrl::App`은 `PathBuf`를 받아서 `?`가 쿼리가 아니라 경로의
일부로 인코딩된다. 창은 뜨는데 표식이 안 보여 아무도 안 받아갔다(실측: 로그에 "새 창 w2"만
남고 "가져감"이 없었다). 애초에 프로세스 경계를 건너보낼 이유가 없는 정보였다.

### AI에게는 조작보다 읽기·쓰기가 필요하다

"AI가 CLI로 앱을 조작한다"는 그림은 실제로는 거의 필요 없다. README가 전제하듯 **vault를
쓰는 건 Lapis가 아니라 바깥 도구들**이고, 파일을 쓰면 watcher가 반영한다.

그래서 AI에게 필요한 건 **읽기(지금 여기)와 안전한 쓰기(아래 3층)** 이고, 앱 조작은 사람이
터미널에서 쓸 때 편한 것이다. 우선순위를 그렇게 잡는다.

## 아직 없는 것 — 층별 계획

| 층 | 내용 | 상태 | 막고 있는 것 |
|---|---|---|---|
| 1 | 읽기 — `search` · `backlinks` · `list` · `links` · `status` | **있음** | — |
| 2 | 헤드리스 인덱싱 — `lapis index` | **있음** | — |
| 3 | 쓰기 — `lapis tag rename` | **있음** | — |
| 4 | 앱 조작 — `lapis open <노트>` | **있음** | — |

### 3층은 선행 작업이 먼저였다

되돌릴 수 없는 쓰기의 안전장치가 UI 레이어(`stores/vault.ts`)에 갇혀 있었다. `#202`에서
태그 이름 바꾸기가 `backupAndWrite`를 쓰려고 export하며 이미 한 발 걸쳤고, CLI가 세 번째가
되려 했다.

`#212`에서 `$lib/safeWrite`로 빼고 IO를 주입받게 했다. 옮기면서 **실패가 성공처럼 보이던
결함**도 드러났다 — 트랜잭션이 아무것도 반환하지 않아 백업 실패 시 모달이 그냥 닫혔다.

CLI를 안 만들더라도 해야 했던 일이다.

## 개발

```bash
npm run check:cli    # 타입 체크 (루트 check는 src/만 본다)
npm test             # 인자 파싱·출력 렌더는 순수 함수라 단위 테스트가 있다
```

`cli/lapis`는 `scripts/bundle-run.sh`를 부른다 — `mcp/lapis-*` 셋과 **같은 러너**다.
