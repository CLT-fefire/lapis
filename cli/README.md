# lapis CLI

터미널에서 Lapis vault를 다루는 명령줄 도구. **앱이 떠 있지 않아도 동작한다.**

> **이 문서가 명세다.** `docs/`는 외부 지식 저장소로의 심링크라(`.gitignore` 참조) **저장소를
> 클론한 곳에는 없다.** 설계 결정을 거기에만 두면 다른 머신에서 이 저장소를 열었을 때 읽을
> 수 없고, 근거를 모르는 채로 같은 결정을 다시 내리게 된다.
>
> 그래서 CLI에 관한 것은 저장소 안, 이 파일에 남긴다 — `mcp/README.md`와 같은 방식이다.
> **무엇을 만들었는지보다 왜 그렇게 했는지**를 적는다. 전자는 코드를 읽으면 되지만 후자는
> 적어두지 않으면 사라진다.

---

## 무엇인가

`lapis-mcp`가 **AI에게** 인덱스를 열어주는 창구라면, 이쪽은 **사람과 스크립트에게** 여는
창구다. 같은 캐시를 읽고 같은 랭킹을 쓴다 — `mcp/query.ts`의 `lapisQuery()`가 두 소비자의
공용 핵이다.

```
                 ┌─ mcp/server.ts   (MCP stdio · AI)
lapisQuery() ────┤
                 └─ cli/main.ts     (argv · 사람 · 스크립트)
```

⚠️ **핵을 복제하지 않는다.** 랭킹이 두 벌이 되는 순간 한쪽만 바뀌어도 아무도 모른다 —
`fullTextOptions.ts` 헤더가 경고하는 바로 그 고장이다. CLI는 `mcp/`에서 가져다 쓰고,
`mcp/`는 CLI를 모른다(의존 방향은 한쪽뿐).

## 실행

```bash
cli/lapis search "멀티 윈도우"
```

호출 시점에 esbuild로 번들한다(약 30 ms). 커밋된 산출물이나 사전 빌드 단계를 두면
소스와 어긋나도 아무 신호가 없다 — `mcp/lapis-mcp`가 같은 이유로 같은 방식을 쓴다.

PATH에 두려면 심볼릭 링크를 건다:

```bash
ln -s "$PWD/cli/lapis" /usr/local/bin/lapis
```

> ⚠️ **Windows에서는 Git Bash가 필요하다.** 래퍼가 `#!/bin/sh` 스크립트다. `cmd.exe`·
> PowerShell용 shim은 두지 않았다 — 유지할 진실이 하나 더 늘고, 이 저장소의 주 개발
> 환경은 macOS다. Git Bash에서 `cli/lapis`를 그대로 부르면 된다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `search <질의>` | 풀텍스트(BM25) + 구조 필터. `lapis_query`와 같은 랭킹 |
| `backlinks <노트>` | 이 문서를 참조하는 문서들. 본문 링크 ∪ frontmatter cross-ref |
| `list <facet>` | `tags` · `topics` · `doc-kinds` 값을 빈도순 열거 |
| `links --broken` | 어느 노트로도 해소되지 않는 본문 링크. 대상별로 묶어 참조 수 순 |
| `status` | 어느 vault를 어느 캐시로 읽고 있는지, 낡았는지 |

### 공통 옵션

| 옵션 | 뜻 |
|---|---|
| `--vault <경로>` | vault 루트. 캐시에 여러 vault가 있을 때 지정 |
| `--json` | 기계가 읽을 형태로. **AI·스크립트는 이걸 쓴다** |
| `--limit <n>` | 기본 10, 상한 50 |
| `--help` | 그 명령의 사용법 |

### `search` 전용

| 옵션 | 뜻 |
|---|---|
| `--tag <t>` | nested prefix — `tech`를 주면 `tech/*` 전부 |
| `--doc-kind <k>` · `--topic <t>` | 정확 일치. ⚠️ frontmatter 선언 기준이라 폴더와 다를 수 있다 |
| `--min-rel <0~1>` | 상대 점수 하한. 결과가 넓을 때 꼬리를 자른다 |
| `--exclude <prefix>` | vault 상대 **문자열 prefix**. 여러 번 줄 수 있다 |
| `--include-archive` | `_memories` 기본 제외를 해제 |

`--min-rel`이 왜 필요한지는 `mcp/README.md`의 **동작 6번**을 보라 — raw 점수는 질의 간
비교가 안 되고, `rel`은 그 질의 안에서 top-1을 1.0으로 둔 값이다.

## 출력 계약

**기본은 사람용**이다. 정렬된 표, 색 없음, 잘린 건 잘렸다고 표시.

**`--json`은 기계용**이고 `lapisQuery()`의 응답을 **그대로** 낸다. MCP 도구가 돌려주는 것과
같은 모양이라, AI가 MCP로 배운 형태를 CLI에서 다시 배우지 않아도 된다.

⚠️ 사람용 출력의 형태는 **계약이 아니다.** 읽기 좋게 바뀔 수 있다. 파싱해야 하면 `--json`을
쓴다. 이걸 명시해 두는 이유는, 안 적어두면 누군가 `awk`로 사람용 출력을 파싱하고 그게 곧
바꾸지 못하는 계약이 되기 때문이다.

## 실패는 소리내어

`mcp/README.md`와 **같은 오류 종류**를 쓴다: `cache_absent` · `version_skew` · `corrupt` ·
`vault_ambiguous` · `vault_not_found` · `path_not_indexed` · `shard_incomplete` · `no_criteria`.

오류는 stderr로 나가고, `--json`이면 stderr에도 JSON으로 나간다 — 기계가 실패 이유를
파싱할 수 있어야 한다.

### 종료 코드

| 코드 | 뜻 |
|---|---|
| `0` | 성공. **결과 0건도 성공이다** |
| `1` | 질의·캐시 오류(위 `kind`들) |
| `2` | 사용법 오류 — 모르는 옵션, 빠진 인자 |

⚠️ **결과 0건을 실패로 두지 않는다.** 스크립트가 "없음"과 "고장"을 구분할 수 있어야 한다.
`grep`이 0건에 1을 내는 관례를 따르지 않는 건 의도적이다 — 이쪽은 검색이 아니라 질의고,
호출부가 `|| true`를 습관적으로 붙이기 시작하면 진짜 실패도 함께 삼켜진다.

### 모르는 옵션은 조용히 무시하지 않는다

오타난 옵션(`--limt 5`)을 무시하면 **기본값으로 돈 결과를 요청한 결과로 오인**한다.
`2`로 죽고 무엇이 잘못됐는지 말한다.

## 설계 판단

### 왜 앱을 거치지 않나

캐시를 직접 읽는다. 앱이 떠 있을 필요가 없고, 떠 있어도 간섭하지 않는다(읽기만 한다).

vault가 캐시보다 새로우면 `status`가 알려주지만 **막지는 않는다** — `mcp/README.md`의
"staleness는 막지 않고 보고한다"와 같은 태도다. 하드 실패 자체가 판단이고, 이 도구는
판단하지 않는다.

### 왜 인덱싱은 아직 없나

**인덱스 생산자는 Rust 하나뿐**이라는 원칙 때문이다(README 설계 원칙). 위키링크·마크다운
링크·프론트매터 추출은 `src-tauri/src/vault.rs`에만 있고, Node에서 다시 짜면 **두 스캐너가
반드시 어긋난다.**

그런데 풀텍스트 shard는 JS MiniSearch로 만든다(`fullTextOptions.ts`). 그래서 헤드리스
인덱싱은 **2단계 파이프라인**이 된다:

```
src-tauri의 bin(vault.rs 재사용) → LinkInfo + stats + fingerprint를 JSON으로
                                 → Node가 fullTextOptions.ts로 shard 빌드 + gzip 저장
```

앱이 IPC 경계를 두고 하는 분업과 **똑같다.** 원칙 두 개(생산자 하나 · 옵션 단일 출처)를
다 지킨다. 아직 만들지 않았을 뿐 방향은 이것이다.

### 왜 서버를 열지 않나

실행 중인 앱을 조작하려면 IPC가 필요한데, **localhost 서버는 쓰지 않는다.**

- README 설계 원칙이 "네트워킹 코드는 없다"이다.
- 로컬의 **아무 프로세스나** vault를 조작할 수 있는 표면이 생긴다. MCP를 기본 OFF로 두고
  "앱이 정할 수 있는 건 질의를 받아줄지뿐"이라고 못박은 태도와 정면으로 어긋난다.

대신 `tauri-plugin-single-instance`가 답이다 — 앱 바이너리를 다시 실행하면 argv가 실행 중인
인스턴스로 전달된다. **리스닝 포트가 없다.** 아직 만들지 않았다.

### AI에게는 조작보다 읽기·쓰기가 필요하다

"AI가 CLI로 앱을 조작한다"는 그림은 실제로는 거의 필요 없다. README가 전제하듯 **vault를
쓰는 건 Lapis가 아니라 바깥 도구들**이고, 파일을 쓰면 watcher가 반영한다.

그래서 AI에게 필요한 건 **읽기(지금 여기)와 안전한 쓰기(아래 3층)** 이고, 앱 조작은 사람이
터미널에서 쓸 때 편한 것이다. 우선순위를 그렇게 잡는다.

## 아직 없는 것 — 층별 계획

| 층 | 내용 | 상태 | 막고 있는 것 |
|---|---|---|---|
| 1 | 읽기 — `search` · `backlinks` · `list` · `links` · `status` | **있음** | — |
| 2 | 헤드리스 인덱싱 — `lapis index` | 없음 | `src-tauri` bin 타깃 + 2단계 파이프라인 |
| 3 | 쓰기 — `lapis tag rename` 등 | 없음 | 백업·롤백 트랜잭션이 `stores/vault.ts`(Svelte store)에 묶여 있다 |
| 4 | 앱 조작 — `lapis open <노트>` | 없음 | `tauri-plugin-single-instance` 도입 |

### 3층이 막혀 있는 이유는 CLI 문제가 아니다

되돌릴 수 없는 쓰기의 안전장치(백업 → 순차 쓰기 → 실패 시 롤백)가 **UI 레이어에 갇혀
있다.** `#202`에서 태그 이름 바꾸기가 `backupAndWrite`를 쓰려고 export하며 이미 한 발
걸쳤다. 두 번째 소비자(CLI)가 생기면 규칙이 둘로 갈릴 위험이 실제가 된다.

CLI를 안 만들더라도 **순수 모듈로 빼두는 게 맞다.** 그게 3층의 선행 작업이다.

## 개발

```bash
npm run check:cli    # 타입 체크 (루트 check는 src/만 본다)
npm test             # 인자 파싱·출력 렌더는 순수 함수라 단위 테스트가 있다
```

`cli/lapis`는 `scripts/bundle-run.sh`를 부른다 — `mcp/lapis-*` 셋과 **같은 러너**다.
예전엔 래퍼마다 같은 38줄(node 탐색 · 임시 파일 레이스 회피 · esbuild 절대 경로)을
복제하고 있었다. 네 번째를 더하는 대신 하나로 합쳤다. 그 38줄에 담긴 것들은
`scripts/bundle-run.sh` 주석에 그대로 옮겨 두었다.
